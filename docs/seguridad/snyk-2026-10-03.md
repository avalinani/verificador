## Cómo se ejecutó

- **Herramienta:** Snyk CLI 1.1307.4, `snyk test --all-projects` sobre `master` (`cbbf996`), con sesión iniciada en la cuenta del proyecto. El proyecto también está conectado a Snyk desde su web.
- **Alcance:** las dependencias de Maven que van en la aplicación (81 analizadas). No incluye las del *plugin* de compilación ni las de los tests.
- **Truco en Windows:** Snyk invoca `mvnw.cmd`, que no encuentra cuando la ruta del proyecto tiene espacios. Se resuelve añadiendo la carpeta del proyecto al `PATH` antes de ejecutarlo.

## ¿Afectan al proyecto?

**Jackson 2 (los cuatro avisos de Jackson): no explotable aquí.**

- Llega solo de forma transitiva, a través de springdoc (`springdoc-openapi-starter-webmvc-ui` → `…-webmvc-api` → `swagger-core`), que lo usa para **generar** el JSON de la documentación OpenAPI.
- El código del proyecto no usa Jackson 2: la aplicación serializa con Jackson 3 (`tools.jackson`), que Snyk no marca.
- Los cuatro fallos se disparan al **leer** JSON malicioso. La API del servicio solo recibe PDF por `multipart/form-data`; nunca deserializa JSON enviado por el cliente con Jackson 2.

**logback (CVE-2026-19880): no explotable aquí.**

- El fallo solo existe con una configuración de logback que use `SiftingAppender` con un discriminador por MDC y un `FileAppender` anidado.
- El proyecto no tiene configuración propia de logback (`logback.xml` / `logback-spring.xml`): usa la de Spring Boot, que escribe en la consola. Tampoco usa MDC ni `SiftingAppender`. Comprobado buscando en `src/main`.

## Decisión

- **Jackson 2:** subir a 2.21.7 cambiando la propiedad `jackson-2-bom.version` del `pom.xml`, la misma que ya se sobrescribe desde T18. No afecta al proyecto, pero el cambio es de una línea, de la misma rama de versiones, y deja el análisis limpio.
- **logback:** se mantiene la 1.5.38 que gestiona Spring Boot 4.1.1. Pasar a 1.6.x por un aviso que no se puede explotar sacaría a logback de la versión probada por Spring Boot. Se revisa cuando una versión de Spring Boot gestione una logback corregida. En Snyk, el aviso se marcaría como ignorado con este motivo.

Estado (2026-10-03):

- **Jackson 2 actualizado a 2.21.7.** `PatchedDependenciesTest` exige ahora 2.21.7 como mínimo: falló con la 2.21.6 resuelta y pasa tras el cambio. `./mvnw verify` pasa con 532 tests, y `/v3/api-docs` y Swagger UI, lo único que usa Jackson 2, siguen respondiendo bien. Al repetir `snyk test` queda **1 aviso**, el de logback.
- **logback:** se mantiene 1.5.38. Marcar el aviso como ignorado en la web de Snyk, con este motivo, es un paso manual del mantenedor.
